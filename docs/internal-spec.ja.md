# 内部仕様書

[English](internal-spec.md) · [README](../README.ja.md) · [外部仕様書](external-spec.ja.md)

## 概要

CLIは引数と現在地を取得し、workspaceの保存先にあるJSONを読み書きする。利用者から見える振る舞いは[外部仕様書](external-spec.ja.md#機能一覧)に定める。配布用にはAmberで一つのBashスクリプトを生成する。

## アーキテクチャとコードの構成

`bin/workspace`からシンボリックリンクで生成済みの`workspace.sh`を実行する。[main.ab](../src/main.ab)が参照管理とコマンド実行の処理に引数を振り分ける。共通のファイル操作には[io.ab](../src/io.ab)を使う。コマンド実行は[refs.ab](../src/refs.ab)でworkspaceの所属先を確かめる。

| ファイル | 担当 |
| --- | --- |
| [main.ab](../src/main.ab) | 引数を解釈し、データの保存先を決め、操作を振り分ける。 |
| [refs.ab](../src/refs.ab) | workspaceを作成・一覧し、現在地から探す。参照を検証・更新し、現在地を含むlinked worktreeを探す。 |
| [run.ab](../src/run.ab) | `scripts.json`を検証し、実行場所を選び、引数をシェルへ渡す。 |
| [io.ab](../src/io.ab) | 環境変数の読み取り、実体パスの取得、ロック、ファイルの保存を行う。 |

変更は`src/*.ab`へ加え、[再生成手順](../README.ja.md#ソースから再生成する)に従って`workspace.sh`を作る。

## 処理設計

### F-001 workspaceを作成する・探す

作成時はslugを検証し、保存先の`.create.lock`を取る。同じ親ディレクトリに一時ディレクトリを用意し、初期状態の`references.json`を書いてから所定のパスへ移動する。対象がすでにあれば、有効なworkspaceかを検証してパスを返す。

`list`と`here`は保存先の直下を走査して参照ファイルを検証し、読めた結果をTSVかJSONで出す。`here`では各workspaceのルートと登録済みディレクトリを現在地の実体パスと比較する。ディレクトリの区切りも含めて判定するため、たとえば`/src/app`と`/src/application`は別の場所として扱う。

### F-002 参照を管理する

追加時は実体パスとファイルの種別を確認する。解除時は保存されたパスをキーにする。どちらも対象workspaceの`.references.lock`を取り、参照ファイルを読み直して該当する配列を更新する。解除するパスがなければ、保存済みのファイルを保持する。

### F-004 名前でコマンドを実行する

`scripts.json`を読み、定義を検証してから実行場所を選ぶ。`refs.ab`は、管理用の配置に含まれる現在地の実体パスから上へたどる。Gitが返すルート、Git管理ディレクトリ、共通ディレクトリを比較し、現在地を含むlinked worktreeを探す。実行場所が決まったら`exec /bin/sh -c`でコマンド文字列を実行する。コマンド名を`$0`、渡された引数を個別の位置引数として渡す。

## データ設計

| ファイル | 保存形式 |
| --- | --- |
| `references.json` | `directories`と任意の`files`を持つオブジェクト。それぞれ重複のない絶対パスの配列。初期値は`{"directories":[]}`。 |
| `scripts.json` | コマンド名をキーとするオブジェクト。値には空でない`command`を指定し、必要なら空でない`cwd`を指定する。 |

## 並行処理とエラー処理

`io.ab`は開いたファイル記述子にmacOSの`lockf`でロックを掛ける。取得は最大15秒待つ。workspaceの作成は保存先のルート単位、参照の書き込みはworkspaceごとで排他する。更新側はロック取得後に、変更の元になるファイルを読む。

JSONの更新では同じ親ディレクトリに一時ファイルを書き、保存先へ移動する。読み取り側はその時点で保存済みのファイルを直接開く。公開前に中断すると一時ファイルやディレクトリが残る場合がある。workspaceの一覧は隠しディレクトリを対象から外す。公開後に中断した場合は、再実行した作成処理が既存の定義を検証する。終了コードと診断の扱いは[外部仕様書](external-spec.ja.md#操作先の選択と終了コード)に従う。

## 設定と権限

既定の保存先は`HOME`から求める。`WORKSPACE_HOME`には絶対パスを指定できる。保存先がすでに存在するときは実体パスへ変換する。CLIは作成前に`umask 077`を設定する。登録されたコマンドはこのマスクを引き継ぎ、利用者の権限で動く。workspaceの設定はローカルのファイルに保存する。

## 検証

リポジトリのルートでAmber 0.6.0-alphaの出力と配布ファイルを照合する。

```sh
amber build --target bash-3.2 --no-proc bshchk src/main.ab - | cmp - workspace.sh
/bin/bash -n workspace.sh
```

動作確認では、一時ディレクトリの絶対パスを`WORKSPACE_HOME`に指定する。[READMEの手順](../README.ja.md#使い始める)を実行する。同じslugで再作成し、共有ディレクトリに関連する候補を表示できることを確かめる。参照を解除しても元ファイルを開けることを確かめる。`run`では、仕様書どおりにGitのworktreeを置いて、実行場所、引数、終了コードを確認する。排他制御は、同じslugの作成と同じworkspaceへの参照追加をそれぞれ同時に行って確認する。
